# ADR 0007 — Sandboxed execution, planning without and with AI, independent verification (M3, M4, M6)

Status: accepted

## Decisions

1. **One sandbox for all untrusted code.** `DockerRunner` runs Python with no network, a read-only root filesystem, a non-root user, all capabilities dropped, no privilege escalation, CPU/memory/PID/time limits, an empty environment and isolated mode (`python -I`). Inputs are copied into a per-run directory and mounted read-only. Outputs must be regular files with safe names, within count and size limits. Code arrives on stdin, never through a shell. Every run is stored (exact code, status, output) and visible in the Runs panel. A 10-test security suite runs against real containers.
2. **Recipes before free-form code.** Built-in, reviewed analysis recipes (profile, aggregate_time, breakdown, decompose, seasonality_by_group) make Reality useful without an AI model and give a model reliable building blocks. Parameters, including column names from untrusted data, reach Python only through `json.loads` of a JSON literal.
3. **Planning without an API key is rule-based, and labelled.** `RuleBasedPlanner` plans only what the recipes can do, from the attached dataset's real schema, and states its assumptions (e.g. the seasonal period) as risks. The UI always says which planner is active.
4. **Planning with Claude uses the same contract.** The Claude planner receives the dataset schema (never raw rows), the recipe and check catalog with parameter JSON schemas, and the capability catalog. It returns structured output: a flat draft whose parameters travel as JSON strings, so the output schema stays strict. Every plan, from any planner, must pass `validatePlan`: recipes and checks exist, parameters are valid, referenced columns exist, checks point at real steps, and required capabilities are enabled or acquired by a step the recipe depends on. Errors go back to the model for another attempt, bounded by the model-call budget.
5. **AI-written code is a fallback with one retry.** Steps without a recipe go to the AI analyst (Claude, only with an API key). It gets one corrective retry that sees the error output. Its code runs in the same sandbox and is recorded like any other run.
6. **Dependencies gate execution.** A step whose dependency did not finish is skipped with the reason, instead of running on missing data.
7. **Verification is independent.** Checks re-compute results from the raw data with plain `csv`/`math`, not with the pandas recipe code, so a recipe bug cannot verify itself. Results are passed (with evidence), failed (with mismatches) or unverified (with the reason). An agent's claim of success is never counted as verification.

## Known gaps

- Containers share the host kernel. Production needs gVisor or microVM isolation (ADR 0004).
- The Claude planner and analyst are implemented and unit-tested through their deterministic parts (prompt context, draft conversion, validation, retry). Live calls to the API were not exercised because no API key was configured.
- Seasonality is reported as real only if a permutation test rejects "no seasonality" at p < 0.05. Statistic: the share of variance explained by position in the cycle (phase R²), computed on the series after removing a quadratic trend; 999 shuffles in time; seeded, so reproducible. This replaced the STL seasonal strength as the statistic (found on real data): with only two cycles, STL strength saturates near 1 for noise as well, so two years of daily bike rentals were reported as "not significant, p = 1.000" despite an obvious summer peak. "Seasonal strength" alone is never used as evidence: it reaches about 0.4 on pure noise. Calibration (`apps/server/eval/calibrate-seasonality.ts`, noise sd 40): false positives 21/400 = 5.25 % with 156 weeks and 27/400 = 6.75 % with 104 weeks (two cycles; slightly above the nominal 5 %, because the quadratic detrending interacts with a single repetition of the cycle); power with 156 weeks 1/10 at amplitude 0.5× noise sd, 10/10 at 1× and 2×; with 104 weeks 10/10 at 2×. The smallest attainable p-value is 0.001; per-group tests are not corrected for multiple comparisons.
- Long daily series (≥ 2 years) are summed to complete calendar weeks (Monday start) before decomposition, with period 52; the decomposition check re-buckets the raw data the same way. A period of 365 on daily data exceeded the sandbox limits and estimates 365 seasonal values from two observations each.
- Upload preparation is heuristic: comment lines, a single all-9s negative marker in an otherwise non-negative column, and year+month columns are handled; anything else (e.g. -1, which can be a real value) is only flagged. The original upload is always kept next to the prepared copy, and each change is listed as a risk in the plan.
